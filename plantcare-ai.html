01 // The Problem

THE PROBLEM

Understanding specific plant-care requirements and investigating common plant diseases is notoriously difficult for everyday plant owners, leading to premature plant loss.

Caring for houseplants and home gardens requires recognizing early, subtle symptoms of distress: leaf chlorosis, dark fungal spotting, moisture stress, and insect damage. For non-botanists, distinguishing between benign environmental shifts and lethal fungal pathogens like Diplocarpon rosae (Black Spot) or Pseudocercospora is nearly impossible.

When plant owners turn to conventional web searches, they encounter contradictory advice, dense botanical literature, or generic forums that fail to account for the specific visual state of their foliage.

Without immediate, structured feedback, caretakers either under-react until leaf degradation becomes irreversible, or over-react by applying improper chemical treatments that further damage the plant.

"Plant owners need instant visual clarity: a reliable tool to photograph a distressed leaf, identify the probable issue, and receive clear, actionable steps before it's too late."

02 // The Proposed Solution

THE PROPOSED SOLUTION

PlantCare AI combines mobile leaf photo capture with cloud-accelerated Groq vision inference to deliver clear condition assessments, confidence ratings, and actionable treatment guidance.

Rather than wading through generic articles, users capture or upload a leaf photo directly on their phone. The application securely sends the image through a FastAPI gateway to the Groq API running Qwen 3.8-27B, parsing the response into a structured diagnosis complete with visible symptom breakdowns and multi-step care advice.

Instant Photo & Gallery Capture

One-tap scanner supporting both live device camera capture and photo gallery selection via Capacitor Camera and HTML5 input fallbacks.

Groq Vision Disease Diagnosis

High-resolution image analysis via Groq API (Qwen 3.8-27B) classifying healthy foliage or diagnosing conditions such as Black Spot, leaf rot, or pest damage.

Confidence & Severity Telemetry

Calculates and renders clear diagnostic confidence percentages (e.g. 90%) and qualitative severity markers (Moderate, Mild, Severe).

Sequential Treatment Recommendations

Generates prioritized, numbered care steps: pruning infected foliage, applying appropriate fungicides, regulating airflow, and watering at soil base.

Categorized Plant Care Knowledge Base

Horticultural guides organized into Watering Frequency, Environmental Humidity, Light Requirements, and Repotting Timing.

Local Scan History & Plant Tracking

Persistent storage saving past diagnostic results with species tags, dates, confidence scores, filterable Healthy vs. Diseased states, and deletion controls.

06 // Technical Implementation

THE GROQ API INTEGRATION

Engineered around a secure client-server architecture where image verification, prompt structuring, and API credentials are kept strictly isolated on the backend.

To provide fast, reliable AI responses without exposing sensitive secrets, PlantCare AI splits duties between a React frontend packaged with Capacitor and a dedicated FastAPI backend microservice.

Stage 01

Client Image Capture

User selects a leaf image via Capacitor Camera or file picker. Converted to a multipart FormData binary payload and transmitted to the API endpoint.

Stage 02

FastAPI Gateway & Auth

FastAPI validates image/* MIME type, checks file integrity with PIL (Image.verify()), and encodes to Base64. GROQ_API_KEY is loaded strictly from server .env.

Stage 03

Groq Vision Inference

Executes chat.completions.create with model ID "qwen/qwen3.8-27b", structured JSON response format, temperature 0.7, and max 1000 tokens.

Stage 04

Structured JSON Extraction

Regex matches valid JSON blocks to strip preamble or reasoning tokens. Frontend maps species against verified rules and calculates health status.

// Verified JSON Schema enforced by PlantCare AI System Prompt:
{
  "plant": "Rose",
  "condition": "Black Spot (Diplocarpon rosae)",
  "confidence": "90%",
  "symptoms": "Leaves exhibit circular purple-black spots with chlorosis...",
  "care": "Remove and dispose of fallen leaves; apply labeled fungicide...",
  "warning": ""
}

Security & API Key Isolation: The Groq API secret is never bundled in the frontend client, APK binary, or client-side JavaScript. All inference requests route through the FastAPI gateway, which returns clean JSON or polite HTTP 429/500 status codes when rate limits are encountered.

07 // Technical Transparency

CHALLENGES & LIMITATIONS

An honest technical assessment separating confirmed constraints currently encountered in testing from botanical risks requiring further validation.

Confirmed Technical Limitations

API Usage & Token Limits

Free-tier Groq API token quotas restrict high-frequency testing sessions. When token thresholds are exceeded, the API returns rate-limiting responses until quota replenishment.

AI Assessment, Not Lab Diagnosis

Vision-language models evaluate visual foliage symptoms from photographs. They cannot analyze soil chemical composition, root nematodes, or microscopic bacterial cultures.

External Cloud Dependency

AI disease scanning requires active network connectivity to reach the FastAPI gateway and Groq API; offline users can access cached care tips and past scans, but cannot run new inference.

Risks Under Ongoing Investigation

Overlapping Disease Symptoms

Different pathogens (e.g. overwatering edema vs. bacterial leaf spot) can produce similar visual chlorosis. Additional validation against horticultural field datasets is ongoing.

Variable Lighting & Focus Artifacts

Direct glare, shadows, and low camera resolution can degrade model confidence. Camera focus guidelines are being tested to improve photo input quality.

Regional Horticultural Verification

Chemical fungicide guidelines require verification with local agricultural authorities, as climate and localized strain resistance vary significantly across geographies.

09 // Reflections & Next Steps

WHAT I LEARNED & FUTURE ROADMAP

Key takeaways from integrating multimodal LLMs with cross-platform mobile apps, alongside a realistic engineering roadmap.

What I Learned

Building PlantCare AI provided direct practical experience in deploying vision-language models into consumer mobile applications. It reinforced the criticality of server-side prompt engineering: forcing strict JSON output schemas, removing model reasoning chatter, and implementing multi-tiered fallback regex parsers to guarantee client stability.

It also illuminated the realities of working with cloud LLM APIs: dealing with image token quotas, latency trade-offs, and ensuring that non-AI features (like local tips and scan history) remain fully functional even when API limits are hit.

Future Roadmap

Sustainable API Quota Tier

Transitioning from test-tier Groq API keys to a dedicated production quota with server-side response caching for identical plant species.

Offline On-Device Fallback

Integrating an on-device TensorFlow Lite / ONNX model to classify common plant diseases locally when network connectivity is unavailable.

Plant Care Push Notifications

Connecting monitored plants to local Capacitor push notifications for customized watering and fertilizing schedules.
