GUIDING PRINCIPLES

HOW I THINK & BUILD

The Rules 01

SOLVE AUTHENTIC FRICTION

Build software that addresses real student, commuter, and user problems rather than hypothetical fluff. If it doesn't solve genuine user pain, don't build it.

The Rules 02

MICRO-INTERACTION CRAFT

Every hover, cursor magnetic pull, drawer opening, and view transition should feel tactile, fast, and natural. Polish is what turns functional tools into joyful experiences.

The Rules 03

RADICAL CLARITY

Direct communication, honest engineering boundaries, verified data, and zero fake stats. If an AI feature is rate-limited, say so clearly. Transparency earns trust.

The Rules 04

IF IT CAN BE SIMPLE, SIMPLIFY

Complexity for complexity's sake is not cool. If a product can do more with less code, clearer hierarchy, and cleaner UI, that's what gets shipped.
